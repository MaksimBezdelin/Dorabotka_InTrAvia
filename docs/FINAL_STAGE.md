# InTrAvia — финальный этап

Решение адаптировано под испытательный полигон ВДНХ и требования задания финального этапа:
маршрутизация по явному графу, промежуточные точки, спецтранспорт, норматив 15 минут,
объяснимый подбор, открытый классификатор дефектов, журнал событий и полевой интерфейс инженера.

## Быстрый запуск

```bash
cd intravia_airport_assignment_update_v17/smart_dispatch_system
python app.py
```

Сервер: `http://0.0.0.0:5000`. Рабочая БД — существующий `database.db`; схема не изменяется.

## Контракт геопозиции

`POST /api/v1/track` — одна точка или пакет `{"points":[...]}`.
Поля: `obj`, `lat`, `lon`, `t` (ISO-8601 UTC), опционально `acc`, `spd`.
Поддерживается также `lng` для совместимости со старыми клиентами.

```bash
curl -X POST http://127.0.0.1:5000/api/v1/track \
  -H 'Content-Type: application/json' \
  -d '{"obj":"e-01","lat":55.8312,"lon":37.6359,"t":"2026-12-03T09:14:20.123Z","acc":5,"spd":0}'
```

Ответ одной точки:

```json
{"accepted": true, "applied": true, "obj": "e-01", "t": "2026-12-03T09:14:20.123Z"}
```

Неизвестный объект → HTTP 200 и `applied:false`; отсутствующие/нечисловые `lat/lon` → HTTP 400.
Пакет возвращает массив результатов в порядке точек. Время без `t` заполняется серверным UTC.

## Маршрутизация

`POST /api/route`:

```json
{
  "start_lat": 55.8337, "start_lng": 37.6180,
  "end_lat": 55.8336, "end_lng": 37.6187,
  "waypoints": [
    {"lat": 55.8313, "lng": 37.6358, "type": "tool"},
    {"parking_id": "3", "delay_sec": 10}
  ],
  "car_lat": 55.8338, "car_lng": 37.6180
}
```

Возможности:
- пеший маршрут по дорогам, разрешённым инженеру в комментариях roads.geojson (service/pedestrian); запасной — pedestrian;
- запасной сервисный/пешеходный граф;
- 1+ промежуточных точек, задержки 30 с (склад) и 10 с (пересадка);
- специальный транспорт по сервисным дорогам со скоростями 5/8/10/20 км/ч;
- чекбокс «Инструмент есть»: если не отмечен, маршрут идёт через ближайший склад (Склад №1/№2), +30 с;
- привязка точек вне графа к **ближайшему ребру** дороги (не только к узлу), затем маршрут идёт по графу;
- прямые линии как маршрут не используются: только короткие access/egress-подходы инженера к дороге и от дороги к стоянке;
- ответ содержит `path`, `distance`, `total_time_min`, `legs`, `waypoints`, `fallback`;
- в сохранённом маршруте есть `snap_start_m`, `snap_end_m` и `graph` — видно, сколько метров инженер идёт до ближайшей дороги и сколько от дороги до стоянки.

## Реализованные API финального этапа

| Метод | Endpoint | Назначение |
|---|---|---|
| POST | `/api/v1/track` | приём геопозиции инженеров, спецтехники и ВС |
| GET | `/api/dispatcher/norms` | прогноз/факт норматива 15 минут и предупреждения |
| GET | `/api/dispatcher/warnings` | только предупреждения диспетчеру |
| POST | `/api/dispatcher/requests/<id>/reassign` | переназначение; после начала работ — с подтверждением старшего смены |
| GET | `/api/defects` | поиск по открытому каталогу дефектов (текст, ATA, категория) |
| POST | `/api/defects` | добавление нового типа дефекта без изменения кода |
| POST | `/api/defects/classify` | классификация свободного текста |
| GET | `/api/defects/ata` | главы ATA и категории |
| GET/PUT | `/api/engineers/<id>/tools` | статус наличия инструмента |
| GET | `/api/event-log` | журнал CSV (или `?format=json`) |
| GET | `/api/event-log.xlsx` | журнал Excel |

## Данные и конфигурация

| Файл | Назначение |
|---|---|
| `static/vdnh/nodes.json`, `edges.json` | официальная сеть полигона: узлы, рёбра, `access`, `access_mode`, скорости, геометрия |
| `static/vdnh/layers.geojson` | официальные слои карты: boundary, edge, stand, facility |
| `static/vdnh/facilities.json`, `stands.json` | объекты, склады, стоянки/зоны обслуживания |
| `static/vdnh/service_zones.geojson`, `objects.geojson` | совместимые слои зон и объектов |
| `static/vdnh/*_positions.geojson` | стартовые позиции инженеров, спецтехники и ВС |
| `data/airport_assignments.json` | привязка инженеров/техники к аэропортам |
| `data/system_settings.json` | текущий аэропорт |
| `data/defect_catalog.json` | открытый каталог дефектов, категорий и глав ATA |
| `data/engineer_tools.json` | статусы инструмента инженеров |
| `data/track_objects.json` | сопоставление ID имитатора: `e-01→eng_7`, `v-01→CAR-V01` |
| `data/event_log.jsonl` | append-only журнал событий |

Графы ВДНХ: официальная сеть nodes.json/edges.json — 801 узел / 842 ребра для инженера (service+pedestrian); спецтранспорт 677/706; taxi и ВПП предназначены для ВС и исключены.
Скорости спецтранспорта берутся из `spd_kmh` каждого ребра: 5/8/10/20 км/ч.
Пешеходная скорость инженера — ровно 5 км/ч. Посадка в спецтранспорт — 10 с, склад — 30 с.

## Соответствие критериям

| Критерий | Реализация |
|---|---|
| Архитектура | презентация `docs/presentation/InTrAvia_final_stage.pdf/.pptx` |
| Функционал | список в презентации и этом файле; проверяется API и UI |
| Процесс разработки/QA/авторство | отдельный слайд с конкретными примерами |
| Адаптация под полигон | карта, зоны, объекты, 4 типа дорог, графы |
| Маршрутизация | граф по комментариям доступа, запрет taxi/ВПП, скорости 5/8/10/20 |
| Промежуточные точки | `/api/route`, карточка «Маршрут с промежуточными точками» |
| Точки вне графа | привязка к ближайшим рёбрам, явные концы маршрута |
| Динамическое обновление | пересчёт по GPS каждые 2.5 с / 8 м |
| Спецтранспорт | сравнение пешком/на машине, посадка, скорости дорог |
| Интерфейс инженера | приём/отклонение, этапы, карта, ETA, инструмент, мобильная версия |
| Полевая работа | GPS 2 Гц, автофиксация прибытия, `norm_ok`/`norm_violation` |
| Геоданные | `/api/v1/track` + интерфейс инженера |
| Цепочка КВС→MCC/ЦПУ→диспетчер→инженер | роли и маршрутизация заявки |
| Права ролей | MEL/AOG — инженер; переназначение после старта — старший смены |
| Статусная модель | валидируемые переходы, история в `routing_history` |
| Многокритериальный подбор | срочность, позиция, допуск/ATA, загрузка, этап работы, последствия, инструмент |
| Объяснимость | таблица кандидатов, причины выбора и отклонения |
| Открытый классификатор | свободный текст, поиск, ATA, добавление типов |
| Несколько AOG | ожидание запчасти, освобождение инженера, возврат в пул |
| Норматив 15 минут | прогноз по маршруту, пересадка/склад, факт по геозоне |
| Риск нарушения | предупреждение заранее + альтернативный инженер |
| Журнал | все события, UTC-метки с мс, время подбора, CSV/XLSX |
| Доп. маршрут | обновление, текстовые и голосовые подсказки, рассогласования |
| Офлайн | очередь GPS/действий, автосинхронизация, пометка устаревшей позиции |
