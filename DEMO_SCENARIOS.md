## Сценарий A. Короткий (5 минут) — «заявка за 15 минут»

**Критерии:** 2, 5–9, 13–17, 20–22.

1. Пилот создаёт заявку: борт `RA-73101`, стоянка `SZ-1`, дефект «течь гидравлики» (свободный текст).
2. MCC видит заявку, проверяет ATA/MEL, передаёт в ЦПУ.
3. ЦПУ передаёт диспетчеру.
4. Диспетчер открывает таблицу кандидатов: допуск, занятость, ETA, загрузка, score, причина отказа; назначает лучшего.
5. Инженер (телефон) принимает заявку → на карте маршрут: пешком или машина, ETA.
6. Диспетчер показывает карту: инженеры AT-0001…, транспорт vehicle-0N, борта RA-…
7. Журнал: заявка, кандидаты (`duration_ms`), назначение, статусы.
8. Выгрузка журнала CSV/XLSX.

**Ожидаемо:** заявка проходит всю цепочку, маршрут по графу, ETA, события в журнале.

## Сценарий B. Живой инженер на ВДНХ (критерии 10–12, 20–22, Д2)

1. Инженер логинится на телефоне (`kuznetsov/eng123`), разрешает GPS.
2. Диспетчер назначает ему заявку (стоянка в зоне `мс-XX`).
3. Инженер идёт по маршруту; на карте диспетчера метка AT-0001 движется по SSE.
4. При входе в геозону стоянки — **автоприбытие**, событие `arrival`, в журнале `elapsed_min / eta_min / delta_min`.
5. Если выйти из зоны интернета — очередь GPS-точек накапливается и досылается; позиция помечается устаревшей.
6. Норматив: предупреждение за 5 минут, нарушение — в журнал.

**Ожидаемо:** движение в реальном времени, автоприбытие без кнопки, запись в журнал.

## Сценарий D. Маршрут со складом и спецтранспортом (критерии 6, 9, Д1)

1. Построить маршрут через **склад** (инструмент, +30 с) и **посадку на спецтранспорт** (+10 с).
2. Сравнить «пешком» и «с машиной»: система выбирает быстрейший вариант.
3. Включить `force_transport` — маршрут принудительно с машиной (`CAR-001`).
4. Показать точку вне графа: маршрут подходит к графу пунктиром и далее идёт по дорогам.

**Ожидаемо:** waypoints, задержки, сравнение, принудительный транспорт.

## Сценарий E. Тестовые режимы организаторов (3.1–3.3)

1. **Пауза:** `POST /api/requests/<rid>/test_options {"paused":true}` → точка агента не применяется (`applied:false, reason:'paused'`); снять паузу.
2. **Таймер:** `{"regulation_minutes":1}` → warning/breach в журнале без GPS.
3. **Транспорт:** `{"force_transport":true}` → `using_car:true`.

**Ожидаемо:** три режима работают на отдельной заявке, живую не ломают.

## Быстрые API-команды для ведущего

```python
import requests
B = 'http://127.0.0.1:5000'
s = requests.Session(); s.post(B+'/api/auth/login', json={'email':'pilot1@aeroflot.ru','password':'pilot123'})
r = s.post(B+'/api/dispatch', json={'source':'pilot','pilot_name':'Демо','pilot_rank':'КВС',
    'aircraft':'RA-73101','parking_id':'SZ-1','fault_type':'hydraulic_leak',
    'description':'Течь гидравлики'})
rid = r.json()['request_id']; print(rid)
# далее MCC→ЦПУ→диспетчер и назначение — через UI или API из сценариев
```

- `POST /api/requests/<rid>/test_options` — `{regulation_minutes, force_transport, paused}`
- `GET /api/faults/classify?text=...`, `GET /api/faults/catalog`
- `GET /api/v1/events/export.csv`, `/export.xlsx`
- `POST /api/v1/track` — `{obj, lat, lon, t?, acc?, spd?}` или `{points:[...]}`

## Если что-то пошло не так

| Симптом | Быстрое решение |
|---|---|
| Телефон не открывает Funnel | Выключить Tailscale на телефоне, авиарежим 5 с, открыть HTTPS-ссылку |
| Карта диспетчера пустая | Проверить `/api/v1/agents`; нажать «Разместить агентов…» и включить автоотправку |
| Точки не двигаются | Проверить SSE `/api/v1/stream`; обновить страницу; проверить CORS-прокси выключен |
| Заявка не назначается | Проверить статус/занятость инженера, `awaiting_parts` |
| Отчёт не отправляется | Перелогиниться (одна сессия), проверить статус `in_progress` |
| Funnel 404/таймаут | Проверить, что сервер на 5000 запущен один раз; `funnel status` |
