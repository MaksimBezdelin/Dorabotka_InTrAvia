## Критично

### C-1. API и дашборды были открыты без авторизации
- Было: `session` не использовалась, любой мог читать и менять заявки.
- Исправление: `app.py:65` — `AUTH_REQUIRED` включён по умолчанию;
  `app.py:303` — `_enforce_server_auth`: `/api/*` без сессии → 401,
  запись по префиксам ролей → 403, дашборды → 302 на `/login.html`.
  Публичными оставлены только контрактные точки `/api/v1/track`,
  `/api/v1/stream`, `/api/v1/agents`, `/api/v1/snapshot`,
  `/api/location`, `/api/parking`, `/api/route` и `/api/auth/session`.
- Проверка: анонимный `GET /api/engineers` → 401; `GET /dispatcher/dashboard.html` → 302.

### C-2. Пароли хранились открытым текстом
- Было: таблица `users.password` содержала пароли как есть.
- Исправление: `app.py:209` — `hash_password` (werkzeug scrypt);
  `app.py:217` — `verify_password` принимает старый открытый пароль один раз
  и возвращает флаг апгрейда; вход `app.py:2414` перезаписывает его хэшем.
  `tools/migrate_passwords.py` мигрировал 17 учётных записей.
- Остаточный риск: демонстрационные пароли (`admin123` и т. п.) слабые —
  менять перед публичным стендом.

### C-3. `.env` и `database.db` в индексе git
- Было: секрет Flask и база с персональными данными попадали в публичный репозиторий.
- Исправление: `.env` уже в `.gitignore`; `database.db` убран из индекса
  (`git rm --cached`), шаблон `.env.example` не содержит секретов.
- История git не переписывалась. Старые коммиты по-прежнему содержат прежние
  версии файлов; при необходимости — `git filter-repo` и ротация `SECRET_KEY`.
- Восстановление локальной базы: положить `database.db` из резервной копии
  рядом с `app.py` (сервер сам не создаёт БД).

### C-4. XSS через пользовательские строки в `innerHTML`
- Было: в `templates/engineer/dashboard.html` заголовок задачи, уведомления и
  подпись машины вставлялись без экранирования; в
  `templates/dispatcher/dashboard.html` — карточка активной заявки, модальное
  окно и отчёт инженера. Сценарий: пилот указывает борт
  `<img src=x onerror=...>`, диспетчер открывает карточку — скрипт исполняется
  в его сессии.
- Исправление: `escapeTaskHtml` в инженерном дашборде
  (`templates/engineer/dashboard.html:1106`, `:434`, `:694`),
  `escapeHtml` в диспетчерском (`templates/dispatcher/dashboard.html:3795`,
  `:3865`). Мобильные страницы уже использовали `esc()`.
- Проверка: строка с `<`/`"` отображается как текст, DOM не исполняет её.

## Высоко

### H-1. Нет проверки роли на сервере для изменяющих API — исправлено
- `app.py:225` `WRITE_ROLE_PREFIXES`: `/api/mcc/` и `/api/cpu/` → MCC,
  `/api/dispatcher/` → диспетчер, `/api/pilot/` → пилот,
  `/api/engineer/` → инженер, пользователи и очистка → админ.
- Остаточный риск: часть общих ручек (`/api/requests/<id>`, `/api/dispatch`)
  доступна любой авторизованной роли. Осознанно: цепочка
  пилот → MCC → диспетчер → инженер использует общий объект заявки.
  Для ужесточения — отдельная матрица действий.

### H-2. CORS был открыт на `*` — исправлено
- `app.py:67`, `app.py:94`: CORS включается только при явном `CORS_ORIGINS`;
  по умолчанию same-origin.

### H-3. Захардкоженный fallback `secret_key` — исправлено
- Ключ берётся из `SECRET_KEY`; при отсутствии генерируется случайный
  (`secrets.token_hex(32)`) и печатается предупреждение. Сессия не переживёт
  перезапуск без `.env`, но предсказуемого ключа больше нет.

### H-4. Подделка геопозиции через публичный `/api/v1/track` — принятый риск
- Контракт организаторов требует приём точек без сессии. Любой, кто знает
  `obj`, может двигать агента на карте.
- Смягчение: `app.py:6034` валидирует `lat/lon` и известность объекта,
  пишет `ingest_error` в журнал; для стенда — сетевой ACL/токен на прокси.
  Для промышленной эксплуатации нужен подписанный токен устройства.

### H-5. Клиентская проверка роли в дашбордах
- `templates/*/dashboard.html` читают `sessionStorage.userSession` и
  редиректят «не свою» роль. Это UX, а не защита; серверная проверка
  (`app.py:303`) теперь дублирует её. Остаточный риск низкий.

## Средне

### M-1. Публичный SSE-поток
- `/api/v1/stream` (`app.py:6058`) отдаёт позиции всех агентов без сессии.
  Нужен мобильным приложениям и имитатору. В проде — авторизация потока
  или отдельный публичный канал без персональных данных.

### M-2. Rate limit только на вход и только в памяти процесса
- `app.py:203`: 10 неудач за 5 минут на email+IP. При нескольких процессах
  gunicorn лимит не общий; для кластера — Redis/прокси.

### M-3. Cookie без `Secure` по умолчанию
- `app.py:93`: `SESSION_COOKIE_SECURE` включается переменной окружения.
  На HTTPS-стенде обязательно `SESSION_COOKIE_SECURE=1`.

### M-4. Ошибки 500 не раскрывают стек — исправлено
- Обработчики возвращают «Внутренняя ошибка сервера», трассировка только
  в консоль сервера.

### M-5. Журнал событий доступен ролям MCC/диспетчер/админ
- `app.py:6171`, `app.py:6229` — инженеру и пилоту журнал закрыт.
  События содержат имена и координаты; при расширении доступа — фильтрация.
